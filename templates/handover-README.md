- 最近更新：{{DATE}}
- **开新对话，第一条消息只需要一句**：
  **「读 docs/handover/next-session-prompt.md，按它执行」**

## 1. 项目全景（**只做导航，不写状态**）

> ⚠️ 本节刻意不写"做到哪了"。写了就会烂——同一件事写两处、只维护一处，
> 另一处必然漂，而漂的那份恰好在新会话最先读、最信任的位置。
> **状态一律去每条线自己的权威文档看。**

| 线 | 范围 | 状态看哪里 | 阻塞性质 |
|---|---|---|---|
| A. <线名> | <范围> | <权威文档> | <是工作量问题还是外部阻塞> |
| B. <线名> | | | |

**总账（所有待办的唯一清单）**：[tracker](../plan/tracker.md)。
**任何摘要与它冲突，以它为准；发现摘要错了，改摘要而不是改总账。**

## 2. 接手要读的（按顺序）

1. 本文（尤其 §1 的全景）
2. [`next-session-prompt.md`](next-session-prompt.md) —— 本轮做什么
3. 当前交接件 —— **读它最后一个 `## 0x` 节**
   （`grep -n '^## 0' <交接件> | tail -1` 就是它）。
   ⚠️ **不要在这里写死节号**，写死了就会落后而没人发现。
   往前**倒着读，以后写的为准**。
4. [tracker](../plan/tracker.md) 的相关节

## 3. 工作流循环

```
从总账领一项 → 有疑问先改设计 → TDD：先跑到真实 red → 跑门禁
  → 更新总账 → 阶段完成写 docs/testing/ 证据 → 提交
```

**收口时必做的四件**（少一件下一轮就会踩空）：

1. **重写**任务书的任务段（覆盖，不追加），**重画那棵树**
2. 在交接件**追加**一个新状态节，写清**哪些既有结论被本轮订正了**
3. 在 **tracker** 勾选/更新对应条目
4. **不要**把状态复制进本文 §1 —— 那是漂移的唯一来源
